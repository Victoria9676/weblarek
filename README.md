# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две сущности, описывающие данные, — товар и покупатель.

#### Тип TPayment

Вид оплаты заказа. Может принимать одно из двух значений.

```
type TPayment = "Безналичная оплата" | "Наличная оплата";
```

#### Интерфейс IProduct

Описывает товар магазина в том виде, в котором он приходит с сервера.

```
interface IProduct {
  id: string;           // уникальный идентификатор товара
  description: string;  // подробное описание
  image: string;        // имя файла изображения
  title: string;        // название
  category: string;     // категория (определяет цвет фона в карточке)
  price: number | null; // цена в синапсах; null — товар «Бесценно» и его нельзя купить
}
```

#### Интерфейс IBuyer

Описывает данные покупателя, которые он указывает при оформлении заказа.

```
interface IBuyer {
  payment: TPayment; // выбранный вид оплаты
  email: string;     // электронная почта
  phone: string;     // телефон
  address: string;   // адрес доставки
}
```

#### Тип TBuyerErrors

Формат результата валидации: объект, где ключи — имена невалидных полей покупателя, значения — тексты ошибок. Если все поля корректны, объект пуст.

```
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

## Модели данных

Модели данных предназначены для хранения и модификации данных приложения. Каждая модель реализует одну конкретную задачу и функционирует автономно, без зависимостей от других моделей.

#### Класс Catalog

Каталог товаров — компонент, который содержит полный перечень товаров магазина, а также хранит ссылку на товар, выбранный пользователем для детального просмотра.

При создании каталога не нужно передавать никакие данные: он стартует с пустого списка товаров и без выбранного товара.

Поля класса:  
`products: IProduct[] = [];` - массив всех товаров, полученных с сервера.  
`selectedProduct: IProduct | null = null;` - товар, выбранный для подробного отображения; `null`, если ничего не выбрано.

Методы класса:  
`setProducts(products: IProduct[]): void` - записывает массив товаров в модель.
`getProducts(): IProduct[]` - возвращает все товары из модели.  
`getProduct(id: string): IProduct | undefined` - возвращает товар по ID либо undefined, если не найден.
`setSelectedProduct(product: IProduct): void` - устанавливает выбранный товар для отображения.
`getSelectedProduct(): IProduct | null` - возвращает выбранный товар либо null.

#### Класс Basket

Сущность «Корзина» (Basket) реализует хранение и базовые манипуляции с набором товаров, отобранных к покупке.

Инициализация: экземпляр создаётся без параметров; начальное состояние — пустая корзина.

Поля класса:  
`items: IProduct[]` - коллекция товаров, добавленных в корзину.

Методы класса:  
`getItems(): IProduct[]` - получает коллекцию товаров корзины.
`addItem(item: IProduct): void` - добавляет переданный товар в коллекцию.  
`removeItem(item: IProduct): void` - удаляет переданный товар из корзины на основании id.  
`clear(): void` - полностью очищает коллекцию товаров.  
`getTotal(): number` - возвращает суммарную стоимость всех товаров в корзине.  
`getCount(): number` - возвращает количество товаров в коллекции.  
`hasItem(id: string): boolean` - выполняет проверку наличия товара по `id`; результат — булево значение.

#### Класс Buyer

Данные покупателя — это модель, которая собирает и хранит информацию, которую пользователь вводит при оформлении заказа: адрес, телефон, почту и способ оплаты.

При создании объекта не нужно ничего передавать: он сразу готов к работе и изначально содержит пустые значения.

Поля класса:  
`payment: TPayment | null = null` - способ оплаты. Пока пользователь его не выбрал, там хранится null.  
`email: string = ""` - адрес доставки куда везти заказ.
`phone: string = ""` - телефон для связи с покупателем.
`address: string = ""` - электронная почта для чеков и уведомлений.

Методы класса:  
`setData(data: Partial<IBuyer>): void` - выполняет частичное обновление состояния: перезаписывает только переданные поля, оставляя остальные неизменными.  
`getData(): IBuyer` - возвращает текущее состояние модели в виде полного объекта `IBuyer`.  
`clear(): void` - приводит состояние к начальному (все поля — пустые значения).  
`validate(): TBuyerErrors` - выполняет проверку заполненности полей. Критерий валидности — непустое значение. Результат — объект `TBuyerErrors`, содержащий только невалидные поля с соответствующими сообщениями об ошибках. Отсутствие поля в результате означает его валидность. Пустой объект — признак успешной валидации всех полей.

## Слой коммуникации

#### Класс LarekApi

Сущность «LarekApi» — компонент коммуникационного слоя, инкапсулирующий бизнес‑ориентированные HTTP‑операции для интеграции с сервисом «Web‑Larёk».
Паттерн проектирования: композиция. Класс не наследуется от базовой реализации API, а зависит от абстракции `IApi`, внедряемой через конструктор. Это обеспечивает слабую связность и тестируемость.

Конструктор:  
`constructor(api: IApi)` - принимает объект, соответствующий интерфейсу `IApi` (экземпляр базового класса `Api`), и сохраняет его для выполнения запросов.

Поля класса:  
`api: IApi` - реализация HTTP‑клиента, используемая для запросов к бэкенду.

Методы класса:  
`getProducts(): Promise<IProductsResponse>` - выполняет GET-запрос на эндпоинт `/product/` и возвращает промис с объектом `{ total, items }`, где `items` — массив товаров. инициирует GET‑запрос к `/product/`; результат — промис с объектом `{ total, items }`, с полями total (общее количество) и items (массив товаров).
`postOrder(order: IOrder): Promise<IOrderResult>` - инициирует POST‑запрос к `/order/` с полезной нагрузкой `IOrder`; результат — промис с объектом `{ id, total }` с подтверждением заказа `(id, total)`.






## Слой представления (View)

Классы представления — это компоненты, которые отвечают только за то, как данные показываются на экране. У каждого такого класса есть свой кусок разметки, и он умеет его обновлять. Данные он не запрашивает сам — их передают ему снаружи. Когда пользователь что‑то делает (кликает, вводит текст и т. п.), класс не пытается сам обработать действие, а просто сообщает о нём через событие, которое уходит в презентер. Все эти классы построены на базе общего родителя — класса `Component`.

### Карточки товара

#### Класс Card

Card — это «каркас» для всех карточек товаров в приложении. Сам по себе он не используется — на его основе делают конкретные карточки под разные сценарии: 
-показывает название и цену товара;
-хранит id товара — чтобы по клику или другому действию можно было понять, о каком товаре речь;
-использует дженерик `T`: каждый вид карточки может работать со своим типом данных, но при этом пользоваться общей логикой. 
Такой подход избавляет от дублирования кода: не нужно в каждой карточке заново описывать, как выводить название и цену или как хранить id.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - принимает корневой элемент карточки (копию шаблона) и брокер событий.

Поля класса:  
`events: IEvents` - брокер событий для оповещения презентера.  
`cardTitle: HTMLElement` - элемент с названием товара.  
`cardPrice: HTMLElement` - элемент с ценой товара.  
`productId: string` - id товара, к которому относится карточка.

Методы класса:  
`set id(value: string)` - сохраняет id товара.  
`get id(): string` - возвращает id товара.  
`set title(value: string)` - выводит название товара.  
`set price(value: number | null)` - выводит цену: число — как «N синапсов», `null` — как «Бесценно».

#### Класс CardCatalog
Карточка товара в каталоге (шаблон `card-catalog`). Дополнительно выводит категорию и изображение. По клику на всю карточку генерирует событие выбора товара.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - находит элементы категории и изображения; вешает обработчик клика на весь контейнер.

Поля класса:  
`cardCategory: HTMLElement` - элемент категории.  
`cardImage: HTMLImageElement` - элемент изображения.

Методы класса:  
`set category(value: string)` - выводит категорию и задаёт модификатор фона.  
`set image(value: string)` - задаёт изображение товара.

Генерирует событие:  
`card:select` - при клике на карточку; передаёт id товара (презентер откроет подробную карточку).

#### Класс CardPreview
`card-preview` - это подробная карточка товара, которая показывается в модальном окне. 
Она берёт базовый функционал (название, цена, id) от родителя Card, а сверху добавляет категорию, картинку и описание. При этом главная особенность — умная кнопка действия: она сама решает, что показать и как себя вести:
Если товара нет в корзине — показывает «Купить».
Если товар уже в корзине — меняет надпись на «Удалить из корзины».
Если у товара нет цены — показывает «Недоступно» и блокирует кнопку, чтобы нельзя было нажать.
Вся логика переключения состояний вынесена в карточку, но сама обработка клика (добавить/удалить) уходит через брокер событий в презентер — карточка не знает, как реально менять корзину, она только сообщает, что пользователь нажал.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - находит категорию, изображение, описание и кнопку; вешает обработчик клика на кнопку.

Поля класса:  
`cardCategory: HTMLElement` - элемент категории.  
`cardImage: HTMLImageElement` - элемент изображения.  
`cardText: HTMLElement` - элемент описания.  
`cardButton: HTMLButtonElement` - кнопка покупки/удаления.

Методы класса:  
`set category(value: string)` - выводит категорию и задаёт модификатор фона.  
`set image(value: string)` - задаёт изображение товара.  
`set description(value: string)` - выводит описание товара.  
`set inBasket(value: boolean)` - переключает кнопку: в корзине — «Удалить из корзины», иначе — «Купить». При отсутствии цены кнопка блокируется и показывает «Недоступно».

Генерирует событие:  
`card:action` - при клике на кнопку; передаёт id товара (презентер добавит/удалит товар и закроет окно).

#### Класс CardBasket

`card-basket` — это карточка‑строка для отображения товара в корзине. Она берёт базовый функционал (хранение `productId`, работу с шаблоном и событиями) от родителя `Card`, а поверх добавляет специфичные для корзины поля:
номер позиции (индекс в списке);
название и цену (из базового функционала);
кнопку «Удалить».
Вся логика проста: пользователь нажимает «Удалить» — карточка не удаляет товар сама, а просто сообщает об этом через событие. Дальше презентер решает, как обновить корзину и пересчитать итоговую сумму. Шаблон `card-basket` отвечает за верстку строки: колонки с номером, названием, ценой и кнопкой.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - находит элемент номера и кнопку удаления; вешает обработчик клика на кнопку.

Поля класса:  
`cardIndex: HTMLElement` - элемент порядкового номера.  
`cardButton: HTMLButtonElement` - кнопка удаления.

Методы класса:  
`set index(value: number)` - выводит порядковый номер товара в списке.

Генерирует событие:  
`card:delete` - при клике на кнопку удаления; передаёт id товара.

### Формы оформления

#### Класс Form

`Form<T>` — это «скелет» для всех форм в приложении. Сам по себе он не знает, какие именно поля должны быть в форме, — это решают наследники. Но он сразу даёт им «из коробки» всю рутинную логику:

Следит за вводом: как только пользователь меняет поле, форма обновляет своё внутреннее состояние (объект типа `T`) и может сразу запустить валидацию.
Показывает ошибки: если что-то не так, форма хранит текст ошибки и умеет отображать его рядом с нужным полем.
Управляет кнопкой: пока есть ошибки или не заполнены обязательные поля, кнопка «Отправить» заблокирована. Как только всё ок — она становится активной.
Говорит с презентером: все важные события (ввод, отправка, сброс) уходят через брокер событий, чтобы UI не делал ничего сам, а только сообщал о происходящем.
Дженерик `T` нужен, чтобы каждая конкретная форма работала со своим типом данных и при этом TypeScript помогал не ошибиться с именами полей и типами значений.

Конструктор:  
`constructor(container: HTMLFormElement, events: IEvents)` - принимает элемент формы (копию шаблона) и брокер событий; вешает обработчики ввода в поля и отправки формы.

Поля класса:  
`events: IEvents` - брокер событий.  
`submitButton: HTMLButtonElement` - кнопка отправки формы.  
`formErrors: HTMLElement` - элемент для вывода текста ошибок.

Методы класса:  
`set valid(value: boolean)` - активирует или блокирует кнопку отправки.  
`set errors(value: string)` - выводит текст ошибок под формой.

Генерирует события:  
`<имя формы>:change` - при вводе в текстовое поле; передаёт имя поля и его значение (презентер сохранит значение в модель покупателя и проверит валидность).  
`<имя формы>:submit` - при отправке формы (нажатие основной кнопки). Имя формы (`order` / `contacts`) берётся из атрибута `name` формы.

#### Класс Order
`order` — это форма первого шага оформления заказа. Она берёт всю рутинную логику (отслеживание изменений, валидацию, блокировку кнопки, события) от родителя `Form`, а сама фокусируется на специфике шага: выборе оплаты и вводе адреса.

Что она делает «сверху» базового класса:

Обрабатывает кнопки оплаты. Когда пользователь кликает на вариант оплаты, форма не просто меняет значение — она аккуратно обновляет состояние и сразу запускает валидацию (например, чтобы кнопка «Далее» не стала активной, пока не выбран способ).
Валидирует адрес. Проверяет, что адрес не пустой, и показывает ошибку, если поле осталось незаполненным.
Готовит данные для следующего шага. При успешной валидации и отправке форма отдаёт в презентер объект с выбранным способом оплаты и адресом — дальше логика переходит на второй шаг (подтверждение или ввод контактов).
Шаблон для отрисовки — order: в нём уже есть разметка под кнопки оплаты и поле адреса, а Order наполняет их данными и вешает обработчики.

Такой подход позволяет не дублировать типовую логику форм и держать специфику каждого шага в отдельном классе.

Конструктор:  
`constructor(container: HTMLFormElement, events: IEvents)` - находит кнопки выбора оплаты и вешает на них обработчики клика.

Поля класса:  
`paymentButtons: HTMLButtonElement[]` - кнопки выбора способа оплаты.

Методы класса:  
`set payment(value: TPayment | '')` - визуально выделяет выбранный способ оплаты.

Генерирует событие:  
`order:payment` - при выборе способа оплаты; передаёт выбранное значение. Дополнительно использует унаследованные события `order:change` (ввод адреса) и `order:submit` (кнопка «Далее»).

#### Класс Contacts
`сontacts` — это форма второго шага оформления заказа. В отличие от шага с выбором оплаты, здесь нет сложной логики: только два текстовых поля — почта и телефон.

Вся рутина (отслеживание ввода, хранение состояния, блокировка кнопки при ошибках) уже реализована в родителе `Form`, поэтому `сontacts` почти ничего не добавляет поверх. Единственное, что нужно реализовать, — это валидацию: проверить, что поля не пустые, и, возможно, убедиться, что почта похожа на email, а телефон содержит нужное количество цифр. 

Шаблон `сontacts` содержит разметку для двух инпутов — `сontacts` просто связывает их с состоянием формы и вешает нужные обработчики через базовый функционал. Такой подход делает код шага максимально лёгким и понятным: вся сложность вынесена в базовый класс, а шаг отвечает только за свои правила валидации.

Конструктор:  
`constructor(container: HTMLFormElement, events: IEvents)` - использует конструктор `Form`.

Методы класса:  
Собственных нет; использует унаследованные `set valid` и `set errors`.

Генерирует события:  
`contacts:change` - при вводе почты или телефона.  
`contacts:submit` - при нажатии кнопки «Оплатить».

### Страница и модальное окно

#### Класс Page
`page` — это «дирижёр» основной страницы: он не рисует отдельные карточки сам, но управляет тем, как страница ведёт себя в целом:
Собирает и показывает галерею каталога. Создаёт экземпляры `catalogCard` для каждого товара, монтирует их в контейнер и следит за тем, чтобы список обновлялся при фильтрации или пагинации.
Держит в актуальном состоянии счётчик корзины. Когда корзина меняется (товар добавили или удалили), `page` получает событие и сразу обновляет цифру в шапке. Так пользователь всегда видит правильное количество товаров, даже если действия происходили в модальном окне или на другой части страницы.
Не даёт странице скроллиться, когда открыто модальное окно. При закрытии модального окна он возвращает всё как было. 

Вся логика построена на событиях: `page` только реагирует на сигналы и меняет UI. Это позволяет легко менять реализацию галереи или счётчика, не ломая общую структуру страницы.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - находит галерею, счётчик и кнопку корзины; вешает обработчик клика на кнопку корзины.

Поля класса:  
`events: IEvents` - брокер событий.  
`gallery: HTMLElement` - контейнер каталога товаров (`main.gallery`).  
`basketCounter: HTMLElement` - счётчик товаров на иконке корзины.  
`basketButton: HTMLElement` - кнопка открытия корзины.  
`wrapper: HTMLElement` - обёртка страницы (для блокировки прокрутки).

Методы класса:  
`set catalog(items: HTMLElement[])` - выводит карточки товаров в галерею.  
`set counter(value: number)` - выводит количество товаров в корзине.  
`set locked(value: boolean)` - блокирует или разблокирует прокрутку страницы.

Генерирует событие:  
`basket:open` - при клике на иконку корзины (презентер откроет корзину).

#### Класс Modal
`Modal` — это «рамка» для любого модального окна: сам по себе он ничего не решает, но даёт стандартный набор поведения, который нужен почти всегда.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - находит кнопку закрытия и контейнер содержимого; вешает обработчики закрытия (крестик и клик по фону).

Поля класса:  
`events: IEvents` - брокер событий.  
`closeButton: HTMLButtonElement` - кнопка закрытия (крестик).  
`modalContent: HTMLElement` - контейнер для содержимого окна.

Методы класса:  
`set content(value: HTMLElement)` - помещает переданный элемент внутрь окна.  
`open(): void` - открывает окно.  
`close(): void` - закрывает окно и очищает содержимое.  
`render(data: { content: HTMLElement }): HTMLElement` - устанавливает содержимое, открывает окно и возвращает его элемент.

Генерирует события:  
`modal:open` - при открытии (презентер заблокирует прокрутку страницы).  
`modal:close` - при закрытии (презентер разблокирует прокрутку).

### Корзина и успешный заказ

#### Класс Basket
`basket` — это компонент, который показывает, что пользователь положил в корзину, и сколько это стоит. Он не хранит сами товары — это делает презентер или сервис корзины, — но знает, как их красиво показать и что делать, если корзина пустая.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - находит список, элемент суммы и кнопку оформления; вешает обработчик клика на кнопку.

Поля класса:  
`events: IEvents` - брокер событий.  
`list: HTMLElement` - контейнер списка товаров.  
`basketTotal: HTMLElement` - элемент общей стоимости.  
`orderButton: HTMLButtonElement` - кнопка оформления заказа.

Методы класса:  
`set items(items: HTMLElement[])` - выводит строки товаров; при пустом списке показывает «Корзина пуста» и блокирует кнопку оформления.  
`set total(value: number)` - выводит общую стоимость товаров.

Генерирует событие:  
`basket:order` - при клике на кнопку «Оформить» (презентер откроет форму заказа).

#### Класс Success
Экран успешного оформления заказа (шаблон `success`). Показывает списанную сумму.

Конструктор:  
`constructor(container: HTMLElement, events: IEvents)` - находит кнопку закрытия; вешает на неё обработчик клика.

Поля класса:  
`events: IEvents` - брокер событий.  
`description: HTMLElement` - элемент с текстом о списанной сумме.  
`closeButton: HTMLButtonElement` - кнопка «За новыми покупками!».

Методы класса:  
`set total(value: number)` - выводит сумму списания в тексте.

Генерирует событие:  
`success:close` - при клике на кнопку закрытия (презентер закроет окно).
